# 配置与使用云同步

适用版本：0.5.0。需要已安装 [Supabase schema v3](supabase-setup.md)。一个私人项目对应一个人的提示词库，连接只用 URL 和 publishable/anon key，没有登录、订阅或定时任务。

## 首次配置

1. 在 Chrome 扩展管理页重新加载更新后的 Prompt Vault；使用构建目录的用户继续加载 `dist/prompt-vault/`。
2. 打开完整管理页，进入 **设置 → 云同步**。
3. 填入 `https://项目标识.supabase.co` 和 Publishable key（也支持 legacy anon key）。不接受 secret/service_role key。当前仅支持 Supabase 托管域名，不支持自定义域名或自托管地址。
4. 点击 **保存连接**，在 Chrome 提示中允许访问填写的项目域名。未授权则不保存配置。
5. 点击 **测试连接**。出现 schema v3 就绪表示接口可达，此操作不上传提示词。
6. 关闭设置，点击完整管理页顶部 **立即同步**。

URL 和 key 保存在 chrome.storage.local，key 默认遮挡，不进入导出或备份。每台电脑分别配置相同项目；配置不通过 chrome.storage.sync 传播。业务数据和同步进度保存在本机 IndexedDB。

SQL 已部署时不必再次执行。测试连接只验证接口可达性，不上传提示词。

## 触发方式

| 动作 | 云请求 |
| --- | --- |
| 保存连接 | 无业务请求，只保存本地并申请域名权限 |
| 测试连接 | 只调用只读状态接口 |
| 打开管理页 / 侧栏 | 先显示本地，再执行一轮有界增量拉取；可在设置关闭 |
| 新建、编辑、收藏、排序、删除、导入、复制 | 本地操作，不上传 |
| 点击立即同步 | 确认旧上传、拉取增量、上传本地修改并拉取确认 |
| 停留、恢复焦点、恢复联网、浏览器启动 | 不触发云同步 |
| 页面隐藏 / 关闭 | 取消该页面正在进行的同步；不会交给后台继续 |

一轮可能含多页请求，使用固定 highWater，最多约 20 次数据请求和 45 秒；单个网络请求总超时 10 秒。达到上限或失败后停止，显示尚有待处理内容，由用户再次点击继续。没有自动重试。侧栏没有立即同步按钮。

如果 A 修改后没有点立即同步，B 就无法看到这次修改。B 持续打开页面也不会自动更新，需重新打开或到管理页点击立即同步。

## 冲突与备份

同一条数据两边都修改时暂停该变更组，不覆盖本地内容。在 **设置 → 云同步** 查看对比，选择：

- **保留本地**：接受新的云端基线，保留本地修改为待上传。如果云端已经删除，则将保留的本地内容另存为新 ID，避免复活旧记录。
- **采用云端**：应用云端版本，处理前的完整本地存活数据自动保存为恢复备份。

两种选择都会先保留备份；可从下面的备份下拉框导出标准 JSON，必要时通过导入预览恢复。目录关系冲突可能涉及多个文件夹，处理的是整组冲突；预览最多前 10 项、每版前 5000 字，备份保持完整。

处理冲突只改变本机状态，不立即发请求；处理后点击立即同步继续。处理前如果本地数据又变化，旧预览会被拒绝。编辑弹窗内尚未保存的草稿不会被拉取覆盖；保存时若持久化实体已更新，会提示重新检查版本。

## 连接与清空

- **移除配置**只停止联网并移除 URL/key，保留提示词与待同步修改。重新配置相同项目后可以继续确认未完成上传。
- 已与一个项目交换数据后，不允许直接改 URL 把旧进度带到另一项目。迁移前导出 JSON，再明确清空本机并配置新项目。
- **清空本机**不删除云端；本地提示词、待同步修改和冲突恢复备份都会删除。下次拉取会重新下载，先导出需要保留的数据。
- 如果还有结果不确定的上传，清空会被阻止；先点击立即同步确认结果。key 已失效时可在同项目设置中更新 key，再确认。

## 数据与容量边界

同步正文、描述、标签、收藏、目录关系和顺序。使用次数、最近使用与界面偏好留在各设备；远端更新不重置本机使用记录。

每次上传先固定 opId 与载荷并持久化；ACK 丢失时重发原请求。拉取到自己的提交后再移除待确认项，发送期间的新编辑仍保留为下一次变更。不能仅凭 HTTP 200 就清除待发送内容。

提示词按最多 100 项、约 4 MiB 目标分批；大单项允许更大但整组不超过客户端 12 MiB。目录新增/更新和删除分别保留关联组，组内最多 500 项；超限明确停止，不截断内容。当前采用实体全量正文作为每次变更载荷，不是文本字符差分。

同步使用云端基线与本地实体对比，覆盖旧队列裁剪或未登记的历史数据；代价是计算待上传内容时读取本地实体和基线。目前没有万条数据下的同步性能证明。

该权限模式允许持有项目有效 publishable/anon key 的人通过接口读写完整库及历史，配置仅用于自己独立的私人项目。接口权限保护不了已泄露的有效 key；不要把配置放进公开网站、示例或开源包。

实际验证与限制见 [0.5.0 验证记录](reviews/2026-09-19-v0.5.0-sync.md)。
