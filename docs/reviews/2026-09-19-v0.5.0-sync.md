# 0.5.0 主动触发云同步验证

日期：2026-09-19。客户端版本 0.5.0；兼容已提供的 Supabase schema v3 / protocol v1，本轮未修改云端接口。

## 实现范围

设置 → 云同步提供 URL、publishable/anon key、打开时拉取开关、保存/测试/移除配置。只有完整管理页显示立即同步按钮，侧栏初始化后仅拉取。未配置或关闭打开时拉取时不发请求；无 alarms、后台监听、自动重试、Auth 或 SDK 定时刷新。

网络请求在页面内执行，Web Lock 防止跨页面同时运行。先渲染本地，后进行只读协议检查与增量拉取；单请求 10 秒、整轮 45 秒与有界请求次数。页面隐藏/关闭取消同步，不交给后台。

云端基线和冻结 pending 请求写入既有 meta store，数据库版本仍为 1。实体、冲突选择、基线和游标应用在一个本地事务内完成。计算待上传内容不依赖旧占位队列，因此旧队列裁剪不导致漏传。上传结果不确定时保留原 opId/载荷，下次手动重试；拉取到自己的提交才完成确认，期间的新编辑保留。

冲突暂停完整事件，处理前备份完整本地存活数据。远端删除与保留本地相遇时新建 ID；目录删除移出本地新增子项。目录合并形成循环时提供结构冲突选择，不推进游标。清空本机不删除云端，并变更 epoch 拒绝旧响应；存在未确认上传时阻止清空。

## 证据

- 新增同步单元测试验证 17 个场景，包括配置拒绝、冻结上传、ACK 丢失、拉取确认、使用记录保留、内容/结构冲突、旧预览拒绝、删除副本、目录引用、游标和项目切换保护，以及请求头不携带用户 JWT。
- 原有 72 个 Node 测试通过；原有 28 个真实 Chromium 扩展回归通过。
- 新增 5 个 Chromium 同步场景通过：本地配置/显式上传、慢网首屏、冲突备份导出、实际 Web Lock 互斥、权限拒绝及网络失败不重试。安装实际扩展，使用真实 IndexedDB、chrome.storage.local、页面与 Web Locks。
- 界面测试的 Chrome host 授权 API 与远端 HTTP 使用模拟。保存动作仍验证实际 userActivation 为 true、申请的精确 origin 正确；没有验证真人对 Chrome 原生授权提示的点击。
- 同步空白页测试初始化脚本曾因空白页没有 chrome.permissions 而失败；限定初始化到扩展 API 存在时后五项通过。这是测试装置问题，保留失败范围说明。
- `bash scripts/test-supabase.sh` 执行现有 SQL 协议与权限/并发测试，并新增 JavaScript 客户端 → 真实 PostgreSQL 函数集成：上传、模拟第二份本地副本仅拉取、提交成功但响应丢失、期间再次编辑、目录删除传播均通过。网络层由本地适配器调用 psql，不代表 Supabase HTTP 网关联通。

设置页截图使用合成 URL/key 和数据，本地输出为 test-results/sync-settings.png；已检查布局与密钥默认遮挡。构建与包验证结果记录于下方。

## 证明边界

用户报告目标 Supabase 表和验证 SQL 已通过；本轮没有读取用户 key、浏览器 profile 或真实提示词，没有写入用户云库。真实项目的 key/网关/CORS/实际网络，以及原生 host 权限批准，需要配置后使用“测试连接”和立即同步验证。

不声称已完成云端两台真实设备联调、同步万条数据的性能测量或远程 CI。每轮有明确预算，大批量同步可能需要再次手动点击。当前只支持托管 *.supabase.co 项目，SQL 与客户端的组大小、字段限制见 [使用指南](../cloud-sync.md)。

源码进行了事务边界、凭据出口、接口响应验证、生命周期和调用路径自查，没有独立子代理审查证据。后台快捷键入口未改动，未重复执行 macOS 级真实键盘快捷键验收。
